# ORBIT AI — دليل تدريب النموذج خطوة بخطوة

هذا الدليل يشرح **شنو يسوي النموذج، وليش، وشلون تعيد تدريبه بنفسك**.

---

## 1. الفكرة بجملة وحدة

> نعطي النموذج **شنو يشوف القمر الصناعي** حول مكان معيّن، ووياه **القمر والغيوم والوقت**.
> وهو يتعلم يتوقع **شكد السماء مظلمة فعلياً من الأرض** (بوحدة mag/arcsec²).

هذا نوع من التعلّم اسمه **Supervised Regression** (انحدار مُراقَب):
- **المدخلات (Features / X):** أرقام نعرفها لأي مكان بالعالم.
- **الهدف (Target / y):** الرقم اللي نريد نتوقعه، وهو قراءة جهاز SQM الحقيقية.
- **التدريب:** النموذج يشوف آلاف الأمثلة (X ← y) ويتعلم العلاقة بيناتهم.

## 2. البيانات

| الدور | المصدر | ليش |
|---|---|---|
| **الهدف y** | [Globe at Night](https://globeatnight.org/maps-data/) (NOIRLab)، قراءات **SQM** من 2019 لـ 2025 | قياسات أرضية حقيقية من ناس بكل العالم |
| **ضوء المدن** | NASA GIBS، طبقة `VIIRS_Black_Marble` (القمر الصناعي Suomi-NPP) | شنو يشوف القمر الصناعي من الأعلى |
| **القمر والشمس** | خوارزمية SunCalc (ملف `orbit_ml/astro.py`) | ضوء القمر والشفق يسطّعون السماء |
| **الحقيقة المحلية** | صور صديقك المصوّر الفلكي | معايرة النموذج للعراق |

### الميزات (Features): 12 رقم لكل قياس
| الميزة | المعنى الفيزيائي |
|---|---|
| `log_light_point` | ضوء ناسا بالنقطة نفسها |
| `log_light_10km` / `10_50km` / `50_160km` | الضوء بحلقات حول الموقع، لأن توهج المدن يوصل لمسافات بعيدة |
| `log_skyglow` | **قانون Walker**: تأثير المدينة يقل مع المسافة بنسبة d^-2.5 |
| `elevation_km` | كل ما ترتفع، يصير الهواء فوقك أخف والسماء أظلم |
| `moon_illum`, `moon_alt`, `moon_light` | طور القمر وارتفاعه |
| `cloud` | الغيوم: بالمدينة تعكس الضوء، وبالبر تحجب النجوم |
| `sun_alt` | الشفق |
| `solar_hour` | وقت الليل، لأن الأضوية تنطفي بعد نص الليل |

> نستخدم `log` لأن الضوء يتغير بأضعاف (المدينة أسطع من البر بـ 1000 مرة)، والعين تحس بالنسبة مو بالفرق.

## 3. الخوارزمية

**ML مو Deep Learning.** البيانات جدولية وعددها حوالي 6 آلاف صف. على هالنوع من البيانات، نماذج الأشجار تتفوق على الشبكات العصبية (Grinsztajn et al., NeurIPS 2022).

1. **خط الأساس `satellite_only`:** Linear Regression على ضوء النقطة بس. هذا يمثل "شنو يكول القمر الصناعي لوحده".
2. **`random_forest`:** 200 شجرة قرار، وكل وحدة تصوّت.
3. **`orbit_ai`**، وهو النموذج النهائي: **Histogram Gradient Boosting** (نفس فكرة LightGBM).
   - يبني 400 شجرة صغيرة، وكل شجرة تصلّح أخطاء الشجرات اللي قبلها.
   - `loss="absolute_error"`: ما يتأثر كثير بالقراءات الغلط، وبيانات المواطنين بيها ضوضاء.
   - **قيود فيزيائية (monotonic constraints):** نجبره إن "ضوء أكثر = سماء أسطع" و"ارتفاع أكثر = سماء أظلم". بدون هالقيود طلعت بغداد أظلم من الموصل، وهذا غلط.

## 4. الاختبار الصادق: GroupKFold جغرافي

**الغلط الشائع:** تقسيم البيانات عشوائياً. هيچ يصير النموذج يشوف قياس من شارع، ويختبرونه على قياس ثاني من نفس الشارع، فتطلع نتيجته أحسن من الحقيقة (data leakage).

**احنا:** نقسّم العالم لمربعات 0.5° (حوالي 50 كم)، وكل مرة **نخفي مربعات كاملة** ونختبر عليها. يعني الرقم اللي نعلنه هو أداء النموذج على **مناطق ما شافها أبداً**، مثل الموصل.

### النتائج
| | القمر الصناعي وحده | **ORBIT AI** |
|---|---|---|
| متوسط الخطأ (MAE) | 0.81 mag | **0.61 mag** (أحسن بـ **25.7%**) |
| الخطأ الوسيط | 0.62 | **0.37** |
| نسبة التوقعات ضمن ±0.5 mag | 42% | **60%** |
| نسبة التوقعات ضمن ±1 mag | 70% | **80%** |
| صنف Bortle الصحيح (±1) | 79% | **83%** |
| R² | 0.48 | 0.62 |

**فحص إقليمي (13 دولة بالشرق الأوسط):** الراصدون يشوفون نجوم لحد قدر **2.8** بالمعدل، والنموذج العالمي يتوقع **4.1**. يعني سماءنا أسوأ من المتوقع (غبار وضباب)، ولهذا نعاير النموذج بصور محلية.

### الحدود (لازم نقولها بصراحة)
- ضوضاء بقراءات المواطنين، وجزء من الخطأ بالبيانات نفسها. حذفنا القراءات المكتوبة كأرقام صحيحة (17.00، 18.00)، لأن جهاز SQM يعطي رقمين عشريين، فهاي تقديرات مكتوبة باليد وخطأها كان 2.6 ضعف.
- طبقة ناسا مركّب سنة 2016 ومؤشر بصري (مو radiance معايَر).
- أغلب البيانات من أمريكا وأوروبا.
- الغبار (AOD) مو ميزة بعد. هذا تطوير مستقبلي عن طريق CAMS/Open-Meteo.

## 5. شلون تشغّله بنفسك

```bash
cd ml
pip install -r requirements.txt

python 01_download_data.py     # ينزّل بيانات Globe at Night (~25 MB)
python 02_build_dataset.py     # ينظّف ويسحب صور ناسا (~1700 صورة، أول مرة 3–5 دقايق)
python 03_train.py             # يدرّب ويختبر ويصدّر النموذج للموقع
python 04_analyze_photos.py    # يحلّل صور صديقك (بعد ما تحطها)
python 05_make_report.py       # يولّد التقرير الكامل بمجلد reports/
python 06_blackmarble_v2.py all --max-tiles 30   # النموذج v2 ببيانات ناسا 2024 (يحتاج EARTHDATA_TOKEN بـ ml/.env)
python 07_display_places.py    # مواقع توضيحية عشوائية من نينوى لصور المعرض (الموقع الحقيقي يبقى بالتحليل)
```

**المخرجات:**
- **مجلد [`reports/`](../reports/README.md)**: التقرير الكامل، وكل الرسوم (`figures/`)، والجداول (`tables/`)، ونتائج الصور (`photos/`).
- لتحديث التقرير بعد أي تدريب: `python 05_make_report.py`
- `../public/model/sky_model.json`: النموذج اللي يشتغل بالموقع.

### شلون الموقع يشغّل النموذج بدون سيرفر؟
`03_train.py` يحوّل الأشجار لملف JSON (لكل عقدة: الميزة والحد واليسار واليمين والقيمة). بعدها `src/modules/skyModel.js` يمشي على الأشجار بالمتصفح. **تأكدنا إن النتيجة مطابقة لـ sklearn** (الفرق أقل من 0.00003).

> ⚠️ تحذير تعلمته الليلة: **لا تدوّر حدود الأشجار (thresholds).** تدويرها لـ 6 أرقام عشرية غيّر النتائج لحد 0.55 mag.

## 6. صور صديقك (`04_analyze_photos.py`)

### شنو يسوي
1. يقرا من EXIF: الوقت والتعريض والـ ISO والفتحة والموقع.
2. يحوّل الصورة لضوء خطّي (يلغي تصحيح sRGB).
3. يقيس **خلفية السماء** (وسيط بلوكات 32×32، بعد ما يشيل النجوم والأرض).
4. يعدّ **النجوم** على نسخة 1600px موحّدة.
5. يحسب السطوع: `photo_mag = ZP − 2.5·log10(background / (t · ISO/100 / N²))`.
6. يقارن مع توقع ORBIT AI لنفس المكان والوقت. **الفرق (delta) = التصحيح المحلي.**

### صور الواتساب 📱
الواتساب **يمسح كل الـ EXIF** ويضغط الصورة. الكود يتعامل وياها هيچ:
- يتعرّف عليها من الاسم `IMG-20260920-WA0012.jpg`، وياخذ التاريخ من الاسم.
- سطر واحد بـ `photos_log.csv` يكدر يغطي جلسة كاملة: `IMG-20260920-WA*`.
- حد أدنى للضوضاء مبني على خطوة ضغط JPEG، حتى آثار الضغط ما تنحسب نجوم. بالاختبار، الصورة الأصلية ونسختها بالواتساب أعطوا **نفس عدد النجوم**.
- إذا ماكو إعدادات تعريض، يقدّر السطوع من كثافة النجوم، باستخدام علاقة يتعلمها من الصور الكاملة (يحتاج 3 صور كاملة على الأقل).
- وزن أقل بالمعايرة: الأصلية = 1، واتساب HD = 0.7، واتساب عادي = 0.5.

> **أفضل حل:** الصديق يرسل الصور بالواتساب **كـ "مستند / Document"**. هيچ توصل الصورة الأصلية بكل الـ EXIF.

### المعايرة المطلقة
إذا عندكم ولو **صورة وحدة** وياها قراءة SQM (جهاز، أو تطبيق مثل *Loss of the Night*)، حطها بعمود `sqm_measured`. هيچ تصير كل الصور مُعايَرة بشكل مطلق. بدونها، النتيجة نسبية فقط: ترتّب المواقع والليالي صح، بس المستوى المطلق ياخذه من النموذج.
